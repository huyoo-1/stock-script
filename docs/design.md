# A 股大盘拥挤度监控脚本 —— 设计文档

## 1. 项目概述

- **项目名称**：A 股大盘拥挤度监控
- **目标**：每日收盘后自动计算上证指数、创业板指的“大盘拥挤度”，并将结果推送到钉钉群。
- **实现语言**：JavaScript（Node.js）
- **运行策略**：先文档，后编码；本文档确认后再进入代码实现阶段。

---

## 2. 核心指标定义

### 2.1 大盘拥挤度

> **大盘拥挤度** = 成交额排名前 5% 的个股成交额之和 / 当日全市场（指数成分股）总成交额 × 100%

该指标用于衡量市场交易集中度和微观结构健康状况。

### 2.2 阈值含义

| 拥挤度范围 | 状态 | 含义 |
|---|---|---|
| < 40% | 正常 | 市场交易分散，微观结构健康 |
| 40% ~ 50% | 关注区 | 交易集中度上升，需关注局部过热 |
| ≥ 50% | 预警区 |  historically 突破后常伴随市场反转或风格切换，顶部预警信号 |

### 2.3 指数维度

由于上证指数和创业板指成分股不同，拥挤度需要分别计算：

- 取指数当日成分股列表；
- 获取每只股票当日成交额；
- 过滤停牌或成交额为 0 的股票；
- 按成交额降序排序，取前 5% 的股票（向上取整）；
- 分子 = 前 5% 个股成交额之和；
- 分母 = 该指数全部成分股成交额之和。

## 4. 数据源

### 4.1 主数据源

- **东方财富（EM）行情接口**：免费、无需 API Key，可获取指数成分股列表及个股当日成交额。
- 接口形式：HTTP JSON 接口，可直接通过 Node.js 内置 `https` 模块请求。

### 4.2 备选数据源

| 数据源 | 说明 |
|---|---|
| 新浪财经 | 提供个股行情接口，可作为成交额备选 |
| 腾讯财经 | 提供简单的行情接口 |
| 同花顺 iFinD / Tushare / Wind | 稳定性更高，但可能需要授权或付费 |

### 4.3 数据源选择原则

- 优先使用东方财富，免费且覆盖指数成分股；
- 在代码中预留数据源切换接口，便于后续替换；
- 如果主数据源失败，支持降级到新浪财经等备用源。

## 5. 推送规则

### 5.1 推送频率

- **固定时间推送**：每天 A 股收盘后 15:05 推送一次。
- A 股交易时间为 9:30 - 11:30、13:00 - 15:00，预留 5 分钟数据缓冲。

### 5.2 推送内容

每次推送包含：

1. 当前日期；
2. 上证指数、创业板指当日拥挤度及预警级别；
3. 最近 30 个交易日的拥挤度对比表格；
4. 关键结论与风险提示。

### 5.3 推送渠道

- **钉钉群机器人 Webhook**：通过 POST 请求发送 Markdown 或文本消息。
- 支持钉钉安全设置中的“加签”（secret）方式。

## 8. 技术选型

| 模块 | 选型 | 说明 |
|---|---|---|
| 运行环境 | Node.js 18+ | LTS 版本，支持原生 `fetch`（可选） |
| HTTP 请求 | 内置 `https` / `http` | 零外部依赖，减少维护成本 |
| 数据存储 | JSON 文件 | 轻量，无需数据库 |
| 定时调度 | 任务计划程序 / crontab | 根据部署环境选择 |

## 9. 配置项

### 9.1 config.json 示例

```json
{
  "indices": [
    { "name": "上证指数", "code": "000001", "exchange": "SH" },
    { "name": "创业板指", "code": "399006", "exchange": "SZ" }
  ],
  "thresholds": {
    "normal": 40,
    "warning": 50
  },
  "dingtalk": {
    "webhook": "https://oapi.dingtalk.com/robot/send?access_token=xxx",
    "secret": "SECxxx"
  },
  "schedule": "0 5 15 * * *",
  "historyDays": 30,
  "maxRetries": 3
}
```

### 9.2 配置说明

| 字段 | 说明 |
|---|---|
| `indices` | 监控的指数列表，包含名称、代码、交易所 |
| `thresholds.normal` | 正常与关注区的分界值（40） |
| `thresholds.warning` | 关注区与预警区的分界值（50） |
| `dingtalk.webhook` | 钉钉机器人 webhook 地址 |
| `dingtalk.secret` | 钉钉安全设置的加签密钥，可为空 |
| `schedule` | 定时调度 Cron 表达式，默认每天 15:05 |
| `historyDays` | 保留并展示的历史交易日数量 |
| `maxRetries` | 数据拉取失败时的最大重试次数 |

## 11. 关键实现要点

### 11.1 数据拉取

- 使用东方财富接口获取指数成分股；
- 使用东方财富批量行情接口获取成分股成交额；
- 数据拉取失败时重试 `maxRetries` 次；
- 重试均失败时，推送“数据异常”告警并记录错误日志。

### 11.2 拥挤度计算

1. 获取指数成分股列表；
2. 获取每只股票当日成交额（单位：元）；
3. 过滤成交额为 0 或无效的股票；
4. 按成交额降序排序；
5. 计算前 5% 股票数量：`topCount = Math.ceil(totalCount * 0.05)`；
6. 分子 = 前 `topCount` 只股票成交额之和；
7. 分母 = 全部有效成分股成交额之和；
8. 拥挤度 = 分子 / 分母 × 100%，保留两位小数。

### 11.3 历史数据

- 每次运行成功后将结果写入 `data/history.json`；
- 数据结构为数组，按日期顺序排列；
- 推送时取最近 `historyDays` 条记录；
- 重复日期运行会覆盖当天数据，避免重复记录。

### 11.4 钉钉推送

- 支持普通 Webhook 和加签 Webhook；
- 消息类型：Markdown；
- 推送失败时记录 `logs/error.log`。

## 12. 部署方式

### 12.1 Windows 本地（任务计划程序）

#### 12.1.1 前置条件

- 已安装 Node.js（建议 18+ LTS），并能在 PowerShell 中执行 `node -v`；
- 脚本目录已准备就绪：`f:\myfile\stock-script`；
- 已创建 `config.json` 并填写钉钉 webhook 等配置。

#### 12.1.2 打开任务计划程序

1. 按 `Win + R`，输入 `taskschd.msc`，回车；
2. 或在“开始”菜单搜索“任务计划程序”。

#### 12.1.3 创建定时任务

1. 在任务计划程序左侧，点击“任务计划程序库”；
2. 右侧点击“创建任务”（推荐）或“创建基本任务”；
3. 在“常规”选项卡：
   - **名称**：`A股大盘拥挤度监控`
   - **描述**：`每日收盘后计算上证指数、创业板指拥挤度并推送到钉钉`
   - **安全选项**：
     - 选择“不管用户是否登录都要运行”（适合长期挂机）；
     - 勾选“使用最高权限运行”通常不需要，保持默认即可；
     - “配置”选择当前 Windows 版本，如 `Windows 10`。

4. 在“触发器”选项卡：
   - 点击“新建”；
   - **开始任务**：`按预定计划`
   - **设置**：`每天`
   - **开始时间**：`15:05:00`
   - 勾选“已启用”。

5. 在“操作”选项卡：
   - 点击“新建”；
   - **操作**：`启动程序`
   - **程序或脚本**：`node.exe`
   - **添加参数**：`index.js`
   - **起始于（可选）**：`f:\myfile\stock-script`
   - 点击“确定”。

6. 在“条件”选项卡（可选）：
   - 如果电脑可能处于睡眠状态，建议取消勾选“只有在计算机使用交流电源时才启动此任务”；
   - 如果需要唤醒电脑运行，可勾选“唤醒计算机运行此任务”。

7. 在“设置”选项卡：
   - 勾选“允许按需运行任务”；
   - 勾选“如果任务失败，按以下频率重新启动”，可设置为 `1 分钟`，尝试 `3 次`；
   - 勾选“如果任务运行时间超过”，设置为 `10 分钟`；
   - “如果此任务已经运行，以下规则适用”选择“请勿启动新实例”。

8. 点击“确定”保存任务，输入管理员密码确认。

#### 12.1.4 验证任务

1. 在任务计划程序库中找到刚创建的任务；
2. 右键 → “运行”，立即手动执行一次；
3. 观察脚本输出或日志文件 `logs/run.log`，确认消息已推送到钉钉；
4. 如未运行，检查“历史记录”标签查看错误原因。

#### 12.1.5 常见问题

| 问题 | 可能原因 | 解决方法 |
|---|---|---|
| 任务不运行 | `node.exe` 不在系统 PATH | 使用 `node.exe` 的绝对路径，如 `C:\Program Files\nodejs\node.exe` |
| 脚本找不到文件 | “起始于”未填写 | 填写脚本所在目录 `f:\myfile\stock-script` |
| 钉钉没收到消息 | webhook 配置错误 / 网络问题 | 检查 `config.json` 和网络连接 |
| 节假日推送 | 非交易日也会触发 | 脚本内部判断交易日，非交易日直接退出 |

### 12.2 Linux / 服务器（crontab）

```bash
5 15 * * * cd /path/to/stock-script && /usr/bin/node index.js >> logs/run.log 2>&1
```

### 12.3 GitHub Actions

通过 `.github/workflows/daily.yml` 定时触发，每天 15:05（UTC+8 对应 UTC 07:05）。

### 12.4 Docker（可选）

构建轻量 Node.js 镜像，内置 Cron 定时任务，适合长期部署。

## 13. 风险与后续扩展

### 13.1 当前风险

| 风险 | 说明 | 缓解措施 |
|---|---|---|
| 免费数据源失效 | 东方财富接口可能调整或限流 | 预留备选数据源接口 |
| 节假日推送 | 非交易日也会触发调度 | 脚本内部判断交易日，非交易日直接退出 |
| 本地数据丢失 | 仅保存在 `data/history.json` | 定期备份，或后续接入数据库 |

### 13.2 后续扩展

- 增加沪深 300、中证 500、科创 50 等宽基指数；
- 增加阈值触发推送（如突破 50% 时单独告警）；
- 接入数据库或对象存储，持久化历史数据；
- 增加 Web 可视化面板；
- 支持企业微信、飞书等其他推送渠道。
